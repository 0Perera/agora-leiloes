# Story 1.1: Esqueleto do monorepo no ar

Status: em andamento
Branch: `story/1-1-skeleton`
Contexto obrigatório: `CLAUDE.md`, `docs/deploy-notes.md`, `docs/decisions.md`

## Objetivo

Ter API e front rodando local e em produção (tudo no Render), com CI verde, **sem nenhuma regra de negócio**.
Tirar o risco de deploy logo no primeiro dia.

## Fora de escopo

- Entidades de domínio (usuários, lotes, lances...), autenticação, SSE.
- Testcontainers e testes de integração (entram na story dos lances).
- Design e roteamento do front.
- Swagger.

## Pré-requisitos (feitos por mim, fora do agente)

- Docker rodando sem sudo, Node 24 (LTS) e npm instalados.
- Repositório público criado no GitHub.
- Conta no Render.
- Commit inicial direto na `main` com: `CLAUDE.md`, `README.md` (esqueleto), `docs/`, `.github/workflows/pr-title.yml`, `.gitignore`.

## Dependências aprovadas para esta story

API: `@nestjs/config`, `@nestjs/typeorm`, `typeorm`, `pg`, `class-validator`, `class-transformer`.
Front: só o que o template do Vite já traz.
Qualquer outra dependência: perguntar antes.

## Passos

### 1. Postgres local
- `docker-compose.yml` na raiz com um serviço `db`: imagem `postgres:17`, porta 5432, volume nomeado, usuário/senha/banco de desenvolvimento.

### 2. API (`/api`)
- Criar com `npx @nestjs/cli new api --package-manager npm --skip-git --strict`.
- Remover `app.controller`/`app.service` de exemplo.
- `engines.node` no `package.json`.
- `config/`: `@nestjs/config` com validação das envs na inicialização via `class-validator`. A API não sobe se faltar variável.
  Envs desta story: `DATABASE_URL`, `DB_SSL`, `WEB_ORIGIN`, `PORT`. Todas no `api/.env.example`.
- `database/`: TypeORM com `synchronize: false` e SSL ligado só quando `DB_SSL=true`.
  `data-source.ts` para o CLI, com os scripts `migration:create`, `migration:generate`, `migration:run` e `migration:revert`.
- Uma migration inicial vazia (`migration:create`), só para provar que migrations rodam no deploy.
- **Decisão a tomar comigo antes de implementar (vira a próxima entrada livre do `decisions.md`):** como as migrations rodam no Render, já que o free não tem pre-deploy:
  start command `npm run migration:run && node dist/main` ou `migrationsRun: true` no TypeORM.
- `health/`: `GET /health` devolvendo `{ status: 'ok' }`. **Não toca no banco.**
- `main.ts`: escutar em `process.env.PORT`, CORS só para `WEB_ORIGIN`, `ValidationPipe` global com `whitelist: true`.
- Lint: adicionar `complexity: ['error', 10]` e `@typescript-eslint/no-explicit-any: 'error'` à config do Nest. Criar o script `lint:check`, sem `--fix`, para o CI:
  o `npm run lint` padrão do Nest corrige sozinho e esconderia erros no CI.
- Testes: um `health.controller.spec.ts` simples.
  Remover o `test/app.e2e-spec.ts` de exemplo, porque ele sobe o `AppModule` e precisaria de banco. Manter o `test/jest-e2e.json`.

### 3. Front (`/web`)
- Criar com `npm create vite@latest web -- --template react-ts`.
- `engines.node` no `package.json`.
- Estrutura inicial: `src/app/`, `src/features/`, `src/shared/api/client.ts`.
- `client.ts` lê `VITE_API_URL` e expõe `getHealth()`. A página inicial mostra "API: ok" ou "API: indisponível".
  Isso prova que o CORS está certo. O componente não chama `fetch` direto, só o client.
- Lint: adicionar `complexity: ['error', 10]` e `@typescript-eslint/no-explicit-any: 'error'` à config do template. Criar o script `lint:check`, sem `--fix`.
- `web/.env.example` com `VITE_API_URL`.

### 4. CI (`.github/workflows/ci.yml`)
- Roda em `pull_request` e em `push` na `main`.
- Job `api` (working-directory `api`): `npm ci`, `npm run lint:check`, `npm test`, `npm run build`.
- Job `web` (working-directory `web`): `npm ci`, `npm run lint:check`, `npm run build`.
- Node 24 nos dois jobs, com cache do npm apontando para o lockfile de cada pasta.
- Job `readme`: falha se o `README.md` passar de 300 linhas (`test $(wc -l < README.md) -le 300`).

### 5. Deploy
Seguir `docs/deploy-notes.md`. Resumo:
- **Render Postgres:** mesma região da API, versão 17. A API usa a Internal Database URL.
- **Render Web Service:** Root Directory `api`, build `npm ci && npm run build`, start conforme a decisão das migrations,
  Health Check Path `/health`, envs `DATABASE_URL` (URL interna), `DB_SSL=false`, `WEB_ORIGIN`. Não definir `NODE_ENV` no build.
- **Render Static Site:** Root Directory `web`, build `npm ci && npm run build`, publish `dist`,
  rewrite `/*` para `/index.html`, env `VITE_API_URL`.

### 6. Compose completo (D-030, incluído nesta story pela D-035)
- `api/Dockerfile` e `web/Dockerfile` multi-stage, usados só pelo compose. O front é servido por nginx com fallback para `index.html`.
- `docker compose up --build` sobe banco, API e web. Portas do host configuráveis (`DB_PORT`, `API_PORT`, `WEB_PORT`).

### 7. Documentação
- README a partir do esqueleto já commitado, seguindo a seção README do CLAUDE.md: preencher "Ágora", "Rodar local" (compose, migrations, api e web) e o aviso de cold start.
- `docs/decisions.md`: entrada da decisão das migrations.
- `docs/ai-log.md`: entrada da story 1.1.

- [ ] CI verde na PR (jobs `api`, `web` e `readme`) e o check do título da PR passando.
